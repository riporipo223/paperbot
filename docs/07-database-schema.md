## 1. Conventions

- PostgreSQL 16+. The schema must also work on Supabase-managed Postgres.
- **Custom schemas** `ref`, `market`, `intel`, `strategy`, `sim`, `ops`. Nothing goes in `public` ([ADR-0017](32-architecture-decision-records.md#adr-0017-custom-postgres-schemas)). On Supabase, these schemas are **not** added to the PostgREST exposed schemas.
- Enumerations are `text` columns with `CHECK` constraints (easier to evolve than `CREATE TYPE ... AS ENUM`). The allowed values are mirrored in `@paperbot/core` zod enums, and a contract test asserts they match.
- IDs: `uuid` (UUIDv7 generated by the application). Natural on-chain keys are `text` (base58).
- Money: lamports / raw token amounts as `numeric(39,0)` (fits u128). USD as `numeric(24,10)`. Prices as `numeric(38,18)`. Bps as `integer`.
- Timestamps: `timestamptz`. Canonical time column names per [06](06-data-architecture.md) §7.
- Every table has `created_at timestamptz not null default now()`. Only mutable tables have `updated_at`.
- Partitioned tables use `PARTITION BY RANGE (<time column>)` with **daily** partitions named `<table>_pYYYYMMDD`, created ahead by the partition manager (§6).
- Primary keys on partitioned tables include the partition key.

Migrations live in `packages/db/migrations/NNNN_description.sql`. The DDL below is the target state. Phase 02 creates it, split into ordered migrations (§8).

## 2. Entity relationship overview

```text
ref.venues 1─* ref.pools *─1 ref.tokens (base) ; ref.pools *─1 ref.tokens (quote)
ref.tokens 1─* ref.token_safety_observations

intel.wallets 1─* intel.wallet_swaps *─1 ref.tokens
intel.wallets 1─* intel.wallet_round_trips ; intel.wallets 1─* intel.wallet_scores

strategy.strategies 1─* strategy.strategy_versions 1─* strategy.config_versions
strategy.runs *─1 strategy_versions ; *─1 config_versions
strategy.runs 1─* strategy.waves 1─* strategy.wave_transitions
strategy.waves 1─* strategy.signals 1─* strategy.decisions
strategy.decisions 1─0..1 strategy.risk_decisions ; decisions *─0..1 strategy.ai_outputs
strategy.decisions 1─* sim.orders 1─* sim.fills
sim.positions 1─* sim.orders ; sim.positions 1─* sim.position_transitions
sim.ledger_transactions 1─* sim.ledger_entries  (ref → fill/order/run)
strategy.runs 1─* sim.portfolio_snapshots

market.events (append-only log) ← referenced by id from signals/decisions/fills (soft reference: no FK across partitions)
```

Soft references (uuid without FK) are used where the target is partitioned or subject to retention (`market.events`, `market.pool_states`). Integrity is enforced in the application and checked by the reconciliation job.

## 3. DDL by schema

### 3.1 `ref`

```sql
create schema if not exists ref;

create table ref.venues (
  id               text primary key,                -- 'pumpfun_curve','pumpswap','raydium_amm_v4','raydium_cpmm', ...
  display_name     text not null,
  program_id       text not null unique,
  pool_type        text not null check (pool_type in ('CP_VIRTUAL_CURVE','CP_AMM','CLMM','DLMM','ORDERBOOK','OTHER')),
  supported        boolean not null default false,  -- economics + decoders implemented
  fee_model        jsonb not null,                  -- see 17-economics §3 (validated by zod)
  verified_at      timestamptz,                     -- when fee_model/program_id last verified against official source
  verification_ref text,                            -- URL / IDL hash used for verification
  created_at       timestamptz not null default now(),
  updated_at       timestamptz not null default now(),
  check (not supported or (verified_at is not null and verification_ref is not null))
);

create table ref.tokens (
  mint              text primary key,
  token_program     text not null check (token_program in ('spl-token','spl-token-2022')),
  decimals          smallint not null check (decimals between 0 and 18),
  symbol            text,                          -- UNTRUSTED display string
  name              text,                          -- UNTRUSTED display string
  metadata_uri      text,                          -- UNTRUSTED
  supply_raw        numeric(39,0),
  created_slot      bigint,
  first_seen_at     timestamptz not null,
  created_at        timestamptz not null default now(),
  updated_at        timestamptz not null default now()
);

-- Safety facts change over time (authorities can be revoked); keep observations.
create table ref.token_safety_observations (
  id                  uuid primary key,
  mint                text not null references ref.tokens(mint),
  observed_at         timestamptz not null,
  slot                bigint,
  mint_authority      text,                        -- null = revoked
  freeze_authority    text,                        -- null = revoked
  token2022_extensions text[] not null default '{}', -- e.g. transfer_fee, permanent_delegate
  top10_holder_pct    numeric(9,6),                -- optional (getTokenLargestAccounts)
  source              text not null,               -- 'helius.rpc'
  created_at          timestamptz not null default now()
);
create index on ref.token_safety_observations (mint, observed_at desc);

create table ref.pools (
  address          text primary key,
  venue_id         text not null references ref.venues(id),
  base_mint        text not null references ref.tokens(mint),
  quote_mint       text not null references ref.tokens(mint), -- WSOL / USDC
  base_vault       text,
  quote_vault      text,
  state_account    text,                            -- account holding reserves (curve account / pool state)
  created_slot     bigint,
  pool_created_at  timestamptz,
  status           text not null default 'ACTIVE' check (status in ('ACTIVE','MIGRATED','CLOSED','UNKNOWN')),
  migrated_to      text references ref.pools(address),
  first_seen_at    timestamptz not null,
  discovery_source text not null,                   -- 'dexscreener','geckoterminal','onchain'
  created_at       timestamptz not null default now(),
  updated_at       timestamptz not null default now()
);
create index on ref.pools (base_mint);
create index on ref.pools (venue_id);
```

create table market.snapshots (

create index on market.snapshots (subject_mint, observed_at desc);

create table market.ohlcv_bars (
  pool_address   text        not null,
  interval       text        not null check (interval in ('1m','5m','1h')),
  bucket_start   timestamptz not null,
  open numeric(38,18) not null, high numeric(38,18) not null,
  low  numeric(38,18) not null, close numeric(38,18) not null,
  volume_quote_raw numeric(39,0) not null default 0,
  volume_usd     numeric(24,10),
  trades         integer not null default 0,
  buys           integer not null default 0,
  sells          integer not null default 0,
  source         text not null check (source in ('DERIVED','GECKOTERMINAL')),

-- Not partitioned: bounded volume; retention by delete job per interval.

create table market.reference_prices (

## 4. Integrity rules not expressible as simple constraints

| Rule | Enforcement |
|---|---|
| Ledger transactions balance per asset | App check before commit + `DEFERRABLE INITIALLY DEFERRED` constraint trigger on `sim.ledger_entries` |
| A fill's `pool_state_event_id` refers to a `FRESH` state no older than `freshness.pool_state.fill_ms` | App invariant (executor) + reconciliation test |
| `strategy.runs.mode` never `LIVE` | CHECK constraint (§3.4) |
| Order status transitions follow the lifecycle | App state machine + `sim.order_transitions` audit. The DB trigger rejects illegal `from→to` pairs. |
| Position quantities equal ledger balances | Reconciliation job after each fill (in-process) and nightly |

## 5. Deduplication across partitions

The unique index `(received_at, source, source_event_key)` only dedups within one partition key value. Primary dedup is in the application (bounded LRU keyed by `source:source_event_key`, TTL `pipeline.dedup.ttl_seconds`, default 86,400). A duplicate that slips through an engine restart gets a different `received_at` and is stored twice in the log. Replay applies the same LRU dedup, so behaviour is identical. Projections use natural keys (`signature, log_index`), so they stay single. This is recorded as an accepted trade-off.

## 6. Partition management

- `packages/db` exposes `ensurePartitions({table, granularity, aheadDays: 3})` and `dropExpiredPartitions({table, retentionDays, archive})`.
- The engine calls `ensurePartitions` at startup and daily through the scheduler. `pnpm db:partitions` runs the same logic from the CLI.
- A default partition is **not** created. Inserting into a missing partition must fail loudly, and the persister retries after calling `ensurePartitions`.
- Tables and granularity: `market.events` (daily), `market.pool_states` (daily), `market.trades` (daily), `market.snapshots` (daily), `ops.latency_samples` (daily), `ops.provider_health` (daily), `intel.wallet_swaps` (monthly).

## 7. Retention job

Runs daily (scheduler) with config `retention.*` ([26](26-configuration-reference.md)). It applies `dropExpiredPartitions`, deletes expired `market.ohlcv_bars` rows by interval, and archives before dropping when `retention.archive.enabled`.

## 9. Supabase-specific notes

- Keep the custom schemas out of the API-exposed schemas. Enable RLS on every table anyway (deny-all by default), as defence in depth.
- The engine connects with a dedicated DB role (`paperbot_engine`) that has privileges only on the six schemas. Migrations run with the owner role.
- Use the **direct connection or session pooler** for the engine (long-lived connections, `LISTEN` optional). Do not use the transaction pooler for migrations.
- Free-tier storage quota is small relative to the event log (see [06](06-data-architecture.md) §4 and [ADR-0018](32-architecture-decision-records.md#adr-0018-database-hosting)).
